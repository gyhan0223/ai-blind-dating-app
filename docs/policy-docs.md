# 공개 정책 문서 (#12) — 이용약관 · 개인정보처리방침 · 커뮤니티 가이드라인

## 상태

**초안.** 실제 출시 전 법률 전문가 검토와 최신 규정 점검(개인정보 보호법·생체정보 처리·국외 이전·전자상거래법)을 거쳐야 한다.
내용은 코드가 실제로 하는 처리에 맞춰 썼고, 아직 제공하지 않는 기능(외모 매칭·AI 대화 분석·결제)은 제공 중인 것처럼 적지 않았다.

| 항목 | 위치 |
|---|---|
| 본문 | `apps/admin/lib/policyContent.ts` (`[ ]` 표시 값은 운영자가 채운다: 사업자명·연락처·주소·시행일·개인정보 보호책임자·Supabase 리전·Didit 처리 국가·본인확인 기관) |
| 공개 URL | 관리자 웹 `/policy/terms` · `/policy/privacy` · `/policy/community` (로그인 없음) + `/delete-account` (#14) |
| 앱 링크 | 로그인 화면(약관·개인정보), 내 정보(세 문서). `EXPO_PUBLIC_POLICY_BASE_URL` 이 있을 때만 표시 |
| 근거 문서 | `docs/data-retention.md`(보관·삭제) · `docs/moderation-policy.md`(제재) · `docs/face-liveness-didit.md` 10절(생체정보) · `docs/monitoring.md`(로그 마스킹) |

## 반영된 처리 목적 (완료 조건 대응)

- 얼굴/생체정보: 실제 사람 확인·중복 계정 의심 검토 목적, 참조 이미지 1장 서버 전용, 임베딩 없음, 상대·추천에 미사용, 탈퇴 유예 뒤 삭제, 별도 목적 시 별도 동의 (#11).
- 본인확인: 결과값 해시만 저장, 1인 1계정·제한 회피 방지 목적, 원문 미저장.
- SMS(SOLAPI)·DB(Supabase)·라이브니스(Didit)·모니터링(Sentry) 위탁·국외 이전 항목. Didit 처리 국가·보존 설정은 계약/콘솔과 일치시켜야 한다 (미확인 값은 `[ ]`).
- 채팅: 원문 저장 목적(상대에게 제공), 운영자 확인 범위(신고된 대화), AI 분석 없음. 위험 패턴 신호는 유형만 기록.
- analytics: 화면 단위 이벤트·서버 사실 기반 퍼널, 원문 미포함.
- 지원/문의: `POLICY_META.contact` — 실제 메일 주소를 채운다.

## 남은 것 (이 저장소 밖)

- 법률 검토 후 문구 확정, 시행일 기입.
- 생체정보 **별도 동의 화면·서버 증적은 구현됨** (#12 — `docs/face-consent.md`). 남은 것: 동의 문서의 미확정 항목(Didit 처리 국가 · 확인 업체 보관 기간 · 연락처) 기입과 법률 검토 →
  `faceConsentPolicy.ts` 를 `final` 로 올리고 `FACE_CONSENT_VERSION` secret 설정. 그 전까지 production 은 얼굴 수집을 시작하지 않는다.
- 스토어 제출 정보(#19)의 개인정보 URL·계정 삭제 URL 을 이 주소로 넣는다.
